# Reproduction Guide

Use a fresh working copy to reproduce the recorded pipeline. The commands below assume the repository root is the current directory.

## Environment

`requirements.txt` preserves the original pinned dependency set and is UTF-16 encoded. It includes notebook and development dependencies as well as modeling packages.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python src/dacon_wind/metric.py
```

On another operating system, activate the virtual environment with that system's shell command. The main LightGBM route uses NumPy, pandas, scikit-learn, LightGBM and joblib; CatBoost and XGBoost are required for their comparison scripts.

The metric command uses in-memory example data. It checks the implementation without needing competition CSVs. It is not a training or inference run.

## Local Inputs

Obtain the competition data through the [official data page](https://dacon.io/competitions/official/236727/data) under its applicable terms.

| Path | Role |
|---|---|
| `data/raw/train/train_labels.csv` | Timestamped generation labels for the three groups |
| `data/raw/train/ldaps_train.csv` | Training LDAPS weather forecasts |
| `data/raw/train/gfs_train.csv` | Training GFS weather forecasts |
| `data/raw/test/ldaps_test.csv` | Test-period LDAPS weather forecasts |
| `data/raw/test/gfs_test.csv` | Test-period GFS weather forecasts |
| `data/raw/sample_submission.csv` | Official output columns, timestamps and row order |

The documented baseline/ensemble route does not consume SCADA files. Retain official filenames and column names. The loaders parse label and forecast timestamps using pandas and read UTF-8-compatible CSVs with BOM handling.

## Local Validation Route

Start with a complete baseline comparison:

```powershell
python scripts/train_baseline_rf_cv.py
python scripts/train_lgbm_cv.py
```

These scripts train on years before 2024 and evaluate on 2024. Predictions, model bundles and JSON summaries are written under `outputs/`.

To explore the recorded tuned/targeted-weather direction:

```powershell
python scripts/tune_lgbm_cv.py
python scripts/train_lgbm_targeted_weather_cv.py
```

Read each script's input prediction paths before running ensemble or postprocessing evaluation. For example, `evaluate_simple_ensemble_cv.py` loads tuned LightGBM, targeted-weather LightGBM, CatBoost and XGBoost validation files because it evaluates candidates using all four sources. Generating only the two LightGBM files is not enough for that evaluation script.

The final submission route below is separate and needs only its two LightGBM test-prediction sources.

## Submission Dependency Order

| Step | Command | Main artifact |
|---|---|---|
| 1 | `python scripts/train_lgbm_tuned_submit.py` | `submissions/lgbm_003_tuned.csv` |
| 2 | `python scripts/train_lgbm_targeted_weather_submit.py` | `submissions/lgbm_005_targeted_weather.csv` |
| 3 | `python scripts/create_ensemble_submission.py` | `submissions/ens_001_simple_avg.csv` |
| 4 | `python scripts/create_ficr_postprocess_submission.py` | `submissions/lgbm_006_ficr_focus.csv` |
| 5 | `python scripts/create_scale_110_submission.py` | `submissions/lgbm_008_scale_110.csv` |
| 6 | `python scripts/validate_submission.py submissions/lgbm_008_scale_110.csv` | Validation result printed to the terminal |

```powershell
python scripts/train_lgbm_tuned_submit.py
python scripts/train_lgbm_targeted_weather_submit.py
python scripts/create_ensemble_submission.py
python scripts/create_ficr_postprocess_submission.py
python scripts/create_scale_110_submission.py
python scripts/validate_submission.py submissions/lgbm_008_scale_110.csv
```

The two training scripts produce `outputs/predictions/lgbm_003_tuned_test.csv` and `outputs/predictions/lgbm_005_targeted_weather_test.csv`. Step 3 consumes them and writes `outputs/predictions/ens_001_simple_avg_test.csv`.

Steps 4 and 5 each consume that original ensemble prediction. Step 5 also requires the submission from step 4 for comparison/alignment. Its multiplier is applied directly to the ensemble; the two scale factors are not multiplied together.

## Generated Artifacts

| Location | Contents |
|---|---|
| `outputs/models/` | Serialized model/imputer bundles and feature metadata |
| `outputs/predictions/` | Validation or test prediction tables |
| `outputs/logs/` | JSON configuration, data-window, method and artifact summaries |
| `submissions/` | CSVs formatted for the official sample schema |

The model bundles are generated by training scripts; postprocessing scripts operate on prediction files without training additional models. The recorded submission route trains and predicts in the training scripts themselves rather than through a standalone model-loading inference command.

The submission scripts reject existing artifact paths. Some CV scripts write to fixed paths without that guard. Preserve earlier artifacts and use a fresh working copy or inspect the script's output paths before running a comparison.

## Troubleshooting

| Symptom | What to inspect |
|---|---|
| Missing input CSV | Official filenames and the train/test folder layout above |
| Missing ensemble prediction | Run the appropriate member-training step first |
| `FileExistsError` for an artifact | A fixed output name already exists; preserve that run and use a fresh working copy |
| No training or validation rows | Input years do not support the requested time split |
| No labels for a group | That target has no usable training history in the selected fold |
| Forecast ID/timestamp alignment error | Member predictions came from a different sample or row order |
| Missing wind-vector columns | The broad wind variant requires specific component columns |
| Dependency installation/import failure | Python version, active environment and the original pinned package constraints |

Do not sort or drop submission rows to suppress an alignment error. Regenerate predictions against the same sample row order.

## Interpreting Validation

A successful CSV validator run confirms the checks it implements; it does not independently verify weather availability times or model generalization. For a custom sample path:

```powershell
python scripts/validate_submission.py submissions/lgbm_008_scale_110.csv --sample data/raw/sample_submission.csv
```

A new full-data reproduction requires the local dataset and environment. The documentation describes the recorded implementation and command dependencies; it does not report a newly completed full-data training run.
